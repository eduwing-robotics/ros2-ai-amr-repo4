# Troubleshooting

## View 재진입 시 로봇 위치 초기화

**문제:** Factory 또는 Map Status View를 다시 열 때 로봇이 초기 위치에 잠시 나타난다.

**원인:** View 오브젝트가 비활성화되는 동안 표시 컴포넌트가 재초기화되고,
새 WebSocket 프레임을 기다린 뒤에만 좌표를 적용했다.

**해결:** UI Manager가 로봇별 마지막 정상 위치와 방향, 수신 시각을 보관한다.
View 활성화 시 캐시를 즉시 적용하고 이후 `ROBOT_STATUS`로 갱신한다.

**결과:** 화면 전환 첫 프레임부터 마지막 실제 로봇 위치가 유지된다.

## 부분 경로 수신 시 기존 Route 소실

**문제:** 상태만 포함한 부분 `ROBOT_STATUS`가 정상 Waypoint 경로를 지운다.

**원인:** 로봇 상태와 route geometry의 갱신 주기가 다른데, 누락 필드를
빈 경로로 해석해 기존 값을 덮어썼다.

**해결:** 필드 존재 여부를 구분하고 Waypoint 배열이 포함된 메시지에서만
로봇별 경로 캐시를 교체한다. 진행 index와 상태는 기존 geometry에 별도로 적용한다.

**결과:** 부분 메시지 사이에도 현재·다음·완료 Waypoint와 경로 구간이 유지된다.

## 통신 연결과 실제 영상 상태 불일치

**문제:** 카메라 WebSocket은 연결됨으로 보이지만 화면에 프레임이 표시되지 않는다.

**원인:** 소켓 연결 성공을 영상 정상으로 간주해 디코딩 실패, 빈 payload,
Texture 적용 중단을 구분하지 못했다.

**해결:** 연결 상태와 마지막 실제 프레임 적용 시각을 분리해 추적한다.
RawImage에 프레임이 적용된 경우에만 영상 수신 상태를 정상으로 갱신한다.

**결과:** 카메라 상태 표시가 사용자가 보는 실제 영상과 일치한다.

## 이벤트 좌표의 공장 구역명 변환

**문제:** AI 이벤트의 ROS 좌표만으로는 운영자가 공장 내 발생 구역을 빠르게 알기 어렵다.

**원인:** 서버 좌표계와 Unity 2D·3D 레이아웃, 구역 경계가 서로 다른 표현을 쓴다.

**해결:** 측정 레이아웃 설정을 기준으로 ROS 좌표를 맵 로컬 좌표로 변환하고,
정의된 구역 경계에 포함되는지 판정해 구역명을 표시한다. 경계 밖이면 원본
좌표를 유지하고 임의 구역명을 만들지 않는다.

**결과:** 이벤트 팝업과 공장 맵에서 동일한 위치와 구역을 확인할 수 있다.

## 팔레트 운반 위치와 회전 안정화

**문제:** 팔레트 부착·해제 순간에 위치가 튀거나 회전이 불안정하고 잘못된
투하 지점에 놓일 수 있다.

**원인:** 부모 Transform 변경, Rigidbody 상태 전환과 목표 pose 적용을
한 프레임에 수행하면 월드/로컬 좌표가 섞이고 물리 보정이 충돌한다.

**해결:** 픽업 거리와 리프트 높이 임계값을 확인한 뒤 carry point에 부착한다.
부착과 투하는 `Lerp`/`Slerp`와 AnimationCurve로 위치·회전을 보간하고,
허용 반경 안의 가장 가까운 drop slot에만 배치한다. 해제 시 원래 Rigidbody
설정과 부모 관계를 복구한다.

**결과:** 리프트 이동 중 팔레트가 안정적으로 따라가고 지정 위치와 회전으로 놓인다.
