# 문제 해결 과정 (Troubleshooting)

## View 재진입 시 로봇 위치 초기화

| 구분 | 내용 |
| --- | --- |
| 문제 | View를 다시 열 때 로봇이 초기 위치에 표시됐습니다. |
| 원인 | 비활성 View가 새 상태 메시지를 기다린 뒤 좌표를 표시했습니다. |
| 해결 | 로봇별 마지막 정상 위치와 방향을 보관해 활성화 즉시 적용했습니다. |
| 결과 | 화면 전환 첫 프레임부터 마지막 실제 위치를 표시합니다. |

## 부분 경로 수신 시 기존 Route 소실

| 구분 | 내용 |
| --- | --- |
| 문제 | 상태만 포함한 메시지가 정상 Waypoint 경로를 지웠습니다. |
| 원인 | 누락된 경로 필드를 빈 경로로 처리해 기존 값을 덮어썼습니다. |
| 해결 | 필드 존재 여부를 구분하고 정상 Waypoint 배열만 경로에 적용했습니다. |
| 결과 | 부분 메시지 사이에도 현재·다음·완료 경로를 유지합니다. |

## 통신 연결과 실제 영상 상태 불일치

| 구분 | 내용 |
| --- | --- |
| 문제 | WebSocket이 연결됐지만 영상 프레임이 표시되지 않았습니다. |
| 원인 | 소켓 연결 성공만으로 영상 상태를 정상으로 표시했습니다. |
| 해결 | 마지막 실제 JPEG 프레임의 화면 적용 시각을 상태 기준으로 적용했습니다. |
| 결과 | 연결 표시와 사용자가 보는 실제 영상 상태를 일치시켜 표시합니다. |

## 이벤트 좌표의 공장 구역명 변환

| 구분 | 내용 |
| --- | --- |
| 문제 | ROS 좌표만으로 공장 내 발생 구역을 파악하기 어려웠습니다. |
| 원인 | 서버 좌표와 Unity 레이아웃이 서로 다른 좌표 표현을 적용했습니다. |
| 해결 | 측정 레이아웃으로 좌표를 변환하고 정의된 구역 경계를 적용했습니다. |
| 결과 | 이벤트 팝업과 공장 맵에 동일한 위치와 구역을 표시합니다. |

## 팔레트 운반 위치와 회전 안정화

| 구분 | 내용 |
| --- | --- |
| 문제 | 팔레트 부착·해제 시 위치와 회전이 불안정했습니다. |
| 원인 | 부모 Transform 변경과 Rigidbody 전환이 같은 시점에 적용됐습니다. |
| 해결 | 거리·높이 조건과 위치·회전 보간을 운반 상태별로 적용했습니다. |
| 결과 | 픽업부터 지정 위치 투하까지 안정적인 자세를 유지합니다. |
